Accepted Catalog already removes color, supplier and surface-finish links before the material. These immediate ExecuteDelete commands run outside the final SaveChanges transaction, so a final rejection or caller cancellation can leave partial cleanup. The production retrying execution strategy now owns the complete transaction around the existing three scoped link deletions, material removal, save and commit. The material is marked Deleted before the retry delegate. SaveChanges uses acceptAllChangesOnSuccess:false so a successfully saved but rolled-back attempt remains Deleted for replay. AcceptAllChanges runs only after the execution strategy returns successfully. Async transaction disposal rolls back unsuccessful attempts. An ambiguous committed attempt is not declared successful by row absence: replay still requires the tracked material deletion and therefore fails concurrency if the previous commit became durable. Without a durable operation receipt, HTTP 500 with a fully committed atomic deletion is possible in that ambiguous case; no synthetic 204 is returned. Other entity deletion, successful 204/missing 404 behavior, permissions, routes, DTOs, schema and cache invalidation remain unchanged. This is a bounded migration integrity improvement, preserving the target's existing all-three cleanup behavior rather than reproducing partial deletion.

Five HTTP/PostgreSQL executions use the unchanged MaterialCollectionFailureFixture: authorized deletion with all links and unrelated sentinel preservation plus 401/403/wildcard/missing/repeated controls; final material-delete rejection through a disposable test trigger with full graph rollback and subsequent recovery; caller abort at the existing final-save barrier with independent graph readback after host disposal. Test trigger removal runs in finally. Parent rows and all three association families are included in graph comparisons. Every test asserts the actual production-registered execution strategy retries on failure. Two additional real-host cases inject one transient commit transport failure before commit or after a real durable commit; both observe Deleted state on both save attempts. Before-commit rollback retries successfully to 204; after-commit ambiguity replays to a concurrency failure/500 while the durable graph remains fully deleted and unrelated rows are intact. Additional interceptors decorate ConfigureDbContext without replacing provider registration or disabling retries.
